# 开发环境与验证入口

项目使用 Python 3.11、PlatformIO、Arduino-ESP32 2.0.17 和 ESP32-C3。
固定工具链与库版本见[platformio.ini](../platformio.ini)；初始化、依赖安装和构建步骤以
[README 从源码构建](../README.md#从源码构建)为准。

SDK 与 YMODEM 通过固定 commit 的 Git 子模块接入，须执行 `scripts/apply_sdk_patch.py` 和
`scripts/apply_ymodem_patch.py`。构建前只读检查版本和补丁，不覆盖本地依赖修改。

## 目录

| 位置 | 用途 |
| --- | --- |
| `.venv/` | 当前 Python 开发与打包依赖 |
| `.platformio/packages/`、`.platformio/platforms/` | 当前已安装工具链和平台 |
| `.pio/libdeps/` | 当前工程库与主机测试所需头文件 |
| `.pio/build/xteink_x4/` | 当前固件构建输出 |
| `artifacts/firmware/maintenance-20261019/` | 当前交付应用、来源清单与摘要 |
| `artifacts/pc-driver/maintenance-20261019-r1/` | 当前交付 EXE、配套源码、许可与校验文件 |
| `../XTE-Link-备份/` | 历史产物、完整备份和实验记录 |

固件构建钩子先将镜像与来源摘要写入 `backups/firmware/`；本轮结束时按
[归档规则](归档说明.md)迁入外部备份，所有历史版本继续保留。

## 软件检查

[README 软件回归](../README.md#软件回归)列出当前不需要设备或私人字库的完整检查链。
主机 C/C++ 检查在 Windows 使用 MSVC Build Tools，其他系统使用 g++ 或 clang++；
先构建工程，让 PlatformIO 准备固定版本的头文件与分区解析器。

完整字体与 UI 逐像素检查需要自行提供字体输入，参见[MiSans 工具](../tools/misans/README.md)
及[旧字库预览](../tools/font_preview/README.md)。默认路径是生成位置，不保证已有生成物；
历史字库已归档，可通过 `--source-zip`、`--bundle`、`--misans-dir`、`--font` 或 `--font-dir` 显式指定。
测试产生的 `.pio/*-host-test/`、截图、日志及 `build/` 临时输出在验证结束后归档。

## 刷写与回退

不要使用默认 PlatformIO upload。现有设备 app1 `0x650000` 只是已核实设备的布局，不能套用到其他机器。
安装器仅支持已验证的 Pixel 3.0.12 恢复布局及沿用该布局的 XTE-Link；详见[安装器](../pc_driver/INSTALLER.md)。
刷前核对设备、备份、真实分区、OTA、应用与恢复槽摘要，仅更新确认的应用槽，并独立校验。
现存完整备份来自 Pixel 3.0.12，原厂完整备份缺失；历史备份、已刷入版本和验收记录见[归档说明](归档说明.md)。
