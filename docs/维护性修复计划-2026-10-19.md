# XTE-Link 可维护性修复计划

日期：2026-10-19。基线：`fd48aa9`（Add MiSans UI, faster TF transfer and standalone installer）。

状态：A～E 已实施并通过本地软件验证，F 的发行自检已通过；真机验收未完成。
Windows CI 工作流已加入，本地命令链通过；云端运行状态见[仓库 Actions](https://github.com/xiaoyi198/XTE-Link/actions)。实际证据与未验项见 [维护性修复验证](维护性修复验证-2026-10-19.md)。

## 1. 目标与判断依据

让审批失败可见、安装可安全停止、异步操作结果可追踪，并让后续修改能够在干净源码副本中构建和回归。
沿用现有 SDK、YMODEM、PlatformIO、unittest 和主机测试，不引入新的服务、协议或通用框架。

审计附件是问题线索，执行依据为项目约束、当前代码和复核证据。本轮已确认：

| 问题 | 当前证据 | 处理结论 |
|---|---|---|
| DSH 提交失败后回退键盘 | 隔离复现：适配器返回 False，仍调用键盘兜底并报告成功 | 第一优先修复 |
| 刷固件缺少操作确认 | 安装窗口直接启动 all/firmware；默认托盘入口打开安装窗口 | 补明确确认和安全入口，保留既有备份保护 |
| 安装取消边界不完整 | 下载已有逐块检查，等待设备和部分传输阶段仍缺取消检查 | 分阶段补齐，写入与必要校验保持连续 |
| Clash 回执与页面耦合 | handlePush 按页面过滤，返回键还清除 pending | 同时修复接收、导航和超时状态 |
| 设备信息并发访问 | 驱动线程更新 devices/config，窗口直接遍历或读取 | 统一锁保护和快照读取 |
| 构建依赖本地准备状态 | 依赖补丁需手动应用，部分测试依赖本地 PlatformIO 包路径 | 加只读前置校验、干净副本验证和 CI |
| 必读规范未纳入仓库 | 硬件契约与按键约定仍被忽略 | 挑选必要文档纳入版本控制 |

此前复核运行了 78 项相关 PC 测试，全部通过；没有运行全量硬件验收。
这说明现有回归未覆盖部分失败路径，不能据此认定上述问题不存在。
本地两个子模块的修改与已保存补丁通过反向应用检查；它们是现有构建基线，实施时先保留。

## 2. 范围与边界

本轮包含下述 A～F 六阶段，预计拆成 6～8 个独立提交。每个行为修复与对应回归一起提交。
先完成软件修改与验证；固件部署和新版发布作为最后的独立步骤，按实施时用户授权执行。

约束：

- 保留现有分区、引导器、恢复 app0、设备白名单、固件归档和 SHA-256 保护。
- 保留原完整 Flash 备份；日常 app1 更新复用匹配备份，不重复读取整片 Flash。
- 按当前横屏映射理解实体按键，在事件处理与绘图处转换，SDK 键名、阈值和引脚不变。
- 不改灰度视觉策略、不重写显示或 YMODEM 驱动、不为本轮新增平台化抽象。
- 新增状态只表达实际需要的业务区别；优先复用现有 Event、锁、队列和请求 ID。
- 不自动运行真实审批、系统代理/TUN 写入或刷机作为普通测试。

## 3. 实施顺序

### A. 审批失败处理与 DSH 本机边界（优先级 P0）

涉及：`pc_driver/driver.py`、`pc_driver/test_driver.py`；需要独立测试文件时按现有布局添加。

改动：

1. 将“存在 DSH 适配器”与“decide 成功”分开判断。适配器存在时只返回其结果，失败不得调用键盘兜底、写成功记录或覆盖请求状态。
2. 保留显式桥接路径原有兼容入口，本轮不新增兜底开关；正常生产路径不因任何提交错误切换到键盘。
3. DSH 仍默认连接本机；校验可用目标为环回地址，拒绝远端目标，并防止结果 POST 的跨主机重定向携带凭据。
4. 失败日志包含请求 ID、操作及可诊断的异常原因，不包含 Cookie、密钥、WiFi 密码或完整凭据。

验收：

- POST 失败、请求过期、适配器拒绝均返回失败，键盘调用次数为 0，成功日志为 0。
- 成功仅处理一次；重复操作、取消与断连后旧请求均不能被再次接受。
- 本机正常连接保持兼容；非法主机在读取或发送凭据前被拒绝。
- 使用伪凭据和模拟 HTTP/WebSocket，不读取真实 DSH 凭据、不触发真实按键。

### B. 安装入口、共享数据与停止流程（优先级 P1）

涉及：`pc_driver/tray.py`、`pc_driver/install_window.py`、`pc_driver/install.py`、必要的 `pc_driver/tf.py` 调用边界及相关测试。

改动分两次提交，先入口与共享数据，再停止行为：

1. all/firmware 开始前确认目标端口、已知设备身份及实际写入范围；取消确认时不下载、不进入维护模式、不占串口。
2. 双击托盘及首次启动默认展示连接/版本状态；用户显式选择“设备安装与维护”后进入安装入口。复用窗口构建逻辑，避免为了只读入口复制整套窗口。
3. 保留单实例唤起能力，更新相应说明；打开窗口本身不执行设备维护。
4. devices/config 的关联更新在既有锁内完成，UI 读取取得快照后释放锁；磁盘访问、窗口交互与串口等待不长时间持锁。
5. 将当前安装的取消 Event 接入托盘退出请求。退出时先请求停止，显示当前阶段，待维护任务释放设备后再关闭进程。
6. 下载、生成字体、等待设备、文件传输和回读等阶段使用明确的超时/检查点；沿用已有下载逐块取消，补齐遗漏路径。
7. YMODEM 优先使用上游已有取消机制及现有 CAN 收尾；仅在安全边界增加检查，保留候选/旧文件恢复规则，不让两个线程同时读取同一串口。
8. Flash 擦写开始后，完成本次写入及必要校验再响应停止。失败时保留备份和更新记录，明确提示可能需要重试恢复；不通过杀线程或强制退出实现超时。
9. 成功、异常与取消均释放串口、清理维护标记并恢复驱动；用户已请求退出时不重新启动驱动。

停止响应的验收口径：

| 阶段 | 停止策略 | 验收 |
|---|---|---|
| 空闲/确认前 | 立即取消 | 不产生设备写操作 |
| 下载/字体生成 | 下一检查点停止，网络读取有有限超时 | UI 立即显示停止请求；网络正常返回或超时后退出；不发布未校验缓存 |
| 等待重启/设备发现 | 检查取消 Event | 使用模拟时钟验证不必等完整等待期限 |
| TF 候选上传 | 协议安全边界取消并收尾 | 原文件不丢失；重跑可恢复或明确保留冲突 |
| 最终文件切换 | 完成本次切换及必要校验/恢复 | 不在两次改名之间硬停 |
| Flash 写入与校验 | 延迟停止 | 明确显示正在完成写入校验，之后不开始下一安装阶段 |

不承诺所有阶段都在固定 5 秒内退出；必须先说明最坏等待来自哪个有界 I/O 或不可中断步骤。
测试使用可控制的慢下载、断口、阶段失败与取消模拟，不以真实断电验证异常路径。

### C. Clash 请求生命周期脱离页面（优先级 P1）

涉及：`firmware/src/main.cpp`、必要的 `firmware/src/clash_panel.h`、`firmware/tests/settings_test.cpp` 和主机桩。

改动：

1. 按请求 ID 与 pending 状态接收 Clash 回执；页面只决定是否触发绘制。
2. 返回或切换页面不等于撤销已发出的写操作，不直接丢弃其 pending 状态。
3. 沿用单个在途请求，不引入请求队列。新页面读取等待在途操作结束；必要时记录一个“回来后刷新”标记。
4. 超时处理在任何页面生效。对已发出的写请求显示“结果待确认”，不暗示未执行，不自动重放写入。
5. 返回 Clash 时先反映已收到的结果或未确认状态，再执行必要的只读刷新；旧 ID 的迟到回执不得覆盖新请求。
6. 如需记录“读请求/写请求”的区别，增加最小明确字段，避免仅靠页面、文案或等待时长推断语义。

验收：

- 发出节点/开关操作后立即返回菜单，正确 ID 回执仍被接收且不会触发其他页面重绘。
- 离页超时、部分分帧回执、错误回执、旧 ID 回执有明确结果。
- 返回页面不重复发送写命令，单个在途请求不被新读取覆盖。
- 沿用横屏方向映射；原确认/返回行为与其他页面回归通过。

### D. 必要文档与可复现构建（优先级 P1）

涉及：`.gitignore`、`README.md`、`PROTOCOL.md`、必要 `docs/` 文档、`platformio.ini` 与 `scripts/` 构建/补丁脚本。

改动：

1. 精确放行硬件契约、按键方向约定及其必要引用。审查个人路径、设备标识和本地验证附件；不整体公开 docs、backups 或历史开发记录。
2. 整理仓库新建环境、应用补丁、运行测试、构建固件与 EXE 的唯一推荐命令；移除 README 的过期测试数字。
3. PlatformIO 构建前只读校验两个子模块的固定 commit 及“期望补丁已应用”状态；缺失或冲突时立即报错并指出现有修复命令。
4. 保留 SDK 补丁的旧版迁移能力。现有 `apply_sdk_patch.py --check` 表示“可应用或已应用”，不能直接用它证明当前源码已补齐；构建前用反向应用检查或等价的精确校验。
5. 构建过程不自动改写子模块；显式应用补丁仍用现有脚本，不改成 fork 或 `update = none`。
6. 固件归档保留现有字段，追加主仓库 revision/dirty 信息与 SDK 实际源码摘要/补丁状态。期望中的依赖补丁单独说明；允许开发时脏工作区归档，不违反成功构建自动归档的既有规则。
7. 发行构建检查必需包的固定版本及缺失项，提供清晰错误；不自动 pip install，不要求整个开发环境的 pip freeze 与最小依赖集合完全相等。
8. 更新 LAN 握手、帧、序号、时限及明文传输边界的协议文档；核对最终发行包的固件/源码摘要、说明、许可文件与内置负载一致。

验收：

- 用只包含受版本控制文件的干净副本，按 README 初始化固定子模块、显式应用补丁并构建成功；不依赖本机旧缓存、字库或未跟踪脚本。
- 在临时副本模拟缺补丁、错误 commit、补丁冲突，构建前失败且不写坏源码。
- 已应用补丁时重复运行幂等；旧 format-only SDK 状态可正常迁移。
- 本地既有两处子模块修改与完整备份在检查中保持不变。
- 发布构建缺依赖/版本不符时在打包前失败；必要说明/许可/源码文件缺失时不宣布发行成功。

### E. 最小 CI 与回归入口（优先级 P1）

涉及：`.github/workflows/`、`.gitignore`、既有测试脚本及少量测试前置适配。

先用一个 Windows CI 作业覆盖现有工程，不先铺设多平台矩阵：

1. 获取固定子模块，使用 Python 3.11 和项目已锁定的依赖。
2. 显式应用补丁，执行 PlatformIO 正式构建，取得后续测试依赖的固定分区解析器与库头文件。
3. 运行 PC 全量 unittest，以及不依赖私有字库/设备的设置、YMODEM 主机回归。
4. CI 与本地复用同一组命令。测试如果还隐含依赖本机路径或未跟踪文件，应先修前置条件；不通过静默 skip 掩盖缺失。
5. 加入 A～D 的失败路径测试。无需接触真实 Codex/DSH、系统代理、物理设备或 WiFi 密码。

已有入口，实施时核对执行环境后复用：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s pc_driver -p 'test_*.py'
.\.venv\Scripts\python.exe firmware/tests/verify_settings.py
.\.venv\Scripts\python.exe firmware/tests/verify_ymodem.py
.\.venv\Scripts\python.exe firmware/tests/verify_ymodem_interop.py
.\.venv\Scripts\python.exe -m platformio run -e xteink_x4
```

上列为入口清单，不代表任意顺序均可直接运行。干净环境先完成依赖/补丁/PlatformIO 准备，再运行依赖其产物的测试。
当前 `test_install.py` 使用 `.platformio/packages/.../gen_esp32part.py`，设置主机测试使用 `.pio/libdeps`；必须在 CI 中显式满足这些前置条件。
本地私有字库、真实视觉效果、完整字体转换与设备写入属于另行列出的验收，不冒充 CI 已覆盖。

验收：干净 runner 的构建和上述自动回归通过；故意引入 DSH 失败兜底或 Clash 离页丢回执时，对应测试能失败。

### F. 集成验收与交付（优先级 P1）

1. 合并前运行 PC 全量测试、与固件改动相关的主机测试及 PlatformIO 正式构建；记录实际通过、跳过与未验证项。
2. 构建新版 EXE，验证内置负载、说明、依赖记录及源码快照；检查安装窗口、确认取消、停止与单实例唤起。全部测试完成前不更新 README 的“当前版本”。
3. 软件验证完成后准备可审查的部署清单。若执行设备验收，先核对设备、分区/OTA、恢复区与既有备份，再只更新 app1。
4. 真机验收聚焦受影响行为：Clash 离页后回执、返回页面的状态、安装停止后的通信恢复、既有按键映射与基本显示。
5. 停止/断连故障优先通过模拟覆盖；不为验收主动打断真实 Flash 擦写，不自动操作真实 TUN。
6. 保留每版应用固件、归档清单和 SHA-256；发行目录另建版本。最终说明区分软件修复、设备实测与仍待观察的效果。

## 5. 本轮暂缓与审计更正

以下不纳入本轮完成条件，除非后续证据或用户选择扩大范围：

- 灰度/快刷策略调整：有性能收益，但会改变视觉效果，先测量各场景耗时与残影。
- TF 上传期间保持 UI/审批并行：当前 YMODEM 是整文件阻塞调用，移动 network.tick 顺序不足以解决；先保留明确维护状态，不重写协议。
- LAN 加密、密钥迁入 NVS、密钥轮换：属于协议或存储迁移，单独设计兼容与恢复，不自行拼装加密方案。
- 全面重写 Tk 线程模型、拆分 main.cpp、增加通用 esptool 适配层：当前证据不足以支持这类广泛改造；先修已确认的数据竞争与错误处理。
- 重新组织历史二进制、改 Git 发布方式、清理历史或强制回收对象：与本轮运行正确性和维护入口无直接依赖。
- 指标越界保护、采样陈旧状态提示、图库路径边界与验证脚本 assert：保留后续小修候选，先确认可达输入和具体收益，不挤占本轮关键路径。

不采用的原报告推论/方案：

- 未认证连接当前不会因零星字节无限续期；它已有固定约 5 秒截止时间。
- 安装线程从守护 UI 线程启动，会继承 daemon 属性；显式添加 daemon=True 不是停止问题的修复，也不采用超时杀进程。
- cleanupGrayscaleBuffers 恢复屏幕差分基线，不释放内存；“灰度内存泄漏”不能据此成立。
- 普通 submodule update 与强制覆盖不同；当前补丁已保存，不把 fork 作为唯一方案。
- 当前 README 已指向新版安装器，发行目录已有许可与源码包；核查完整性，不沿用“完全缺失”的旧结论。

## 6. 完成标准

- A～E 各阶段的行为与失败路径验收有对应证据，现有兼容路径没有无意回退。
- 干净源码副本能按文档构建，CI 可以复现自动回归，缺前置条件时明确失败。
