# Xteink X4 硬件契约（核实版）

> 目标设备：初代 Xteink X4，ESP32-C3 版本。
>
> 本文件把公开资料中的硬件事实、实现约束和本项目的产品决策分开记录。
> `已确认` 表示至少有官方/社区资料或可复现代码支持；`待实测` 不得作为最终硬件结论。
>
> 这不是 X4 Classic（X4 v2，ESP32-S3）或 X4 Pro 的契约。三者的固件和引脚不能互换。

## 2. 引脚和总线

### 2.1 已确认引脚表

| GPIO | 功能 | 方向/电平 | 备注 |
|---:|---|---|---|
| 0 | 电池电压 ADC | 输入 | 通过分压测量；SDK 默认倍数 2.0 读数合理（拔 USB 约 4.09 V），成品无法拆测，比例未校准 |
| 1 | 按键 ADC 1 | 输入 | 返回、确认、左、右电阻梯 |
| 2 | 按键 ADC 2 | 输入 | 上、下电阻梯 |
| 3 | 电源键 | 输入，低有效 | 也是唤醒输入 |
| 4 | EPD DC | 输出 | |
| 5 | EPD RST | 输出，低有效 | 另有社区资料建议在休眠时保持该线，需实测 |
| 6 | EPD BUSY | 输入，忙电平待实测 | 原资料写低忙，但当前 SDK 的 X4 路径以 HIGH 等待；冲突未消除，必须等待释放后继续发送屏幕命令 |
| 7 | SPI MISO / SD DO | 输入 | 主要供 microSD 使用 |
| 8 | SPI SCLK | 输出 | EPD 与 SD 共用 |
| 10 | SPI MOSI | 输出 | EPD 与 SD 共用 |
| 12 | SD CS | 输出 | |
| 13 | 电池电源锁存 | 输出/保持 | 深睡时的电源保持关键线；不可当作普通空闲 GPIO |
| 20 | USB 检测 | 输入，高电平 = USB 已连接 | 2026-10-16 实测：外部驱动，上拉/下拉读数一致；4 次插拔无抖动；只表示接电，不区分充电/充满 |
| 21 | EPD CS | 输出，低有效 | |

### 2.2 总线规则

- EPD 和 microSD 共用 SCLK、MOSI；CS 不得同时有效。
- 屏幕刷新和 SD 访问必须串行化，并由同一个 SPI 访问层或互斥保护。
- 屏幕不提供可依赖的帧内容回读；应用必须保存自己的显示状态。
- GPIO9 是 ESP32-C3 strapping pin；GPIO8 也是 strapping pin。GPIO18/19 与 USB 功能相关。不能因为“引脚编号存在”就把它们当作可安全扩展脚。
- “所有 GPIO 已 100% 占用”不是芯片事实，而是当前板级连接下的工程结论；如需扩展，必须先看原理图并做电气验证。

## 3. 按键语义

- 设备共有 7 个按键：电源、上、下、左、右、确认、返回。
- 只有电源键是数字 GPIO；其余 6 个按键由 GPIO1/GPIO2 上的电阻梯 ADC 解码。
- ADC 按键只能轮询，不能把它们当作独立 GPIO 中断源。
- 同一 ADC 通道上的两个键不应设计为组合键；跨通道组合是否稳定也要由固件消抖和真机测试决定。
- 建议轮询周期 20–50 ms、消抖约 50 ms；长按和按下/释放由软件状态机实现。
- CircuitPython 的参考值是 16 位刻度；Arduino `analogRead()` 常见为 12 位，但衰减、校准和批次会改变读数。原始阈值必须在目标固件和真机上重新标定，不能直接复制比例换算值。

## 4. 屏幕刷新契约

- 屏幕刷新是物理波形过程，不是普通 framebuffer 重绘。
- 初始化、整屏布局切换和残影清理使用全刷；局部数字更新可使用局部/快速刷。
- 局刷次数、LUT、耗时和残影阈值由实际驱动决定。建议先定义可配置的全刷周期，默认 20–30 次局刷后全刷，但不得把该数值当成面板硬件常数。
- 任何刷新请求都必须等待 BUSY 释放；禁止在刷新期间并发访问 EPD SPI。
- 不设计连续动画、平滑滚动或高频计数器。界面更新粒度应为秒级以上。
- 屏幕断电后会保留最后画面；重新启动时必须主动重绘，并为时效数据显示更新时间或状态。

## 5. 内存与通信约束

- 800×480 单色帧约 48,000 字节（约 47 KiB）。应用默认使用单帧；双帧并非绝对“物理不可能”，但会显著压缩 Wi-Fi 和应用内存，必须通过实测 heap 决定。
- 不使用一次性分配的大型 JSON 文档。消息采用定长/分段解析，运行时记录 free heap。
- 单条消息上限、协议形式（WebSocket、TCP 或 HTTP）属于项目协议决策，不是 X4 硬件契约。若选择 WebSocket，应以实测内存为准，并保留协议层替换能力。
- TLS 是否启用同样属于安全和部署决策，不能仅凭“ESP32-C3 内存小”写成硬件禁止；本项目若采用局域网 PSK/HMAC，必须在协议文档中另行说明。

## 6. 电源和桌面摆件策略

- 初代 X4 支持深度睡眠/硬件电源锁存；社区实现使用 GPIO13 保持电源状态。不能因为项目定位为桌面设备，就声称硬件不支持深睡。
- Wi-Fi 常开功耗高；社区实测显示常在线约数小时，定时唤醒的续航与间隔、固件和网络条件有关。
- 本项目的产品策略是 USB-C 常供电，但仍应保留断电、USB 拔出和网络离线状态显示；这属于产品行为，不是硬件边界。
- GPIO20 已于 2026-10-16 实测：高电平表示 USB 已连接；是否充满无法由它区分。拔 USB 后设备保持唤醒运行并正常刷新。
- 断连时不得继续显示无时间戳的陈旧数据。建议显示 `OFFLINE`、最后更新时间和数据年龄。

## 7. 明确的项目非目标

这些是本项目选择，不是硬件事实：

- 初期不接入额外外设，不改板，不焊线。
- 初期不依赖 microSD；如使用字体或缓存，必须遵守 SPI 串行规则。
- 初期采用 USB 常供电，不以电池续航作为主要验收指标。
- 审批提醒不依赖设备发声；如需声音，由 PC 侧负责。设备只负责显示状态。

## 8. 实机验证清单

在把下列项目写入实现常量前，必须在目标设备上记录结果：

1. GPIO1/GPIO2 每个按键的 ADC 原始值、空闲值、温漂和重复按压范围。
2. ~~GPIO20 USB 检测的高低电平语义，以及插拔边沿是否可靠。~~ 已完成，本地 2026-10-16 电量图标验证记录：4 次插拔无抖动，上拉/下拉读数一致。
3. GPIO13 深睡/唤醒流程；确认不会因电源锁存错误导致无法启动。
4. GPIO5 在休眠保持与否对漏电和唤醒的影响。
5. 实际 free heap：无 Wi-Fi、已连接 Wi-Fi、刷新前后、SD 操作前后。
6. SSD1677 全刷、快速刷、局刷的真实耗时和残影累积。
7. 屏幕实物型号、排线方向和旋转方向；不要仅按网络照片判断。
8. 是否存在未记录的 LED、蜂鸣器或其他板载器件；当前公开资料未证明有可用提示器件。

2026-10-10 已在现有 Pixel 3.0.12 固件完成基础检查：7 个按键响应、屏幕正常刷新、电量页显示充电中；串口记录了刷新耗时。这不等同于上述 GPIO、ADC 和本项目固件验收，详细原始记录保留在本地 2026-10-10 硬件验证档案。
