# 离线字库预览

生成后打开 `artifacts/font-preview/preview_epdfont.html`。字体数据已嵌入，
无需启动服务、联网或选择文件。请勿把 `.template.html` 当作生成后的预览页面。

默认显示 Zheng17、Zheng20、Zheng25 的同一设置列表；可切换自定义文字、
黑白／四级灰度以及实物尺寸／原像素／两倍放大。此设置列表仅用于字号比较，
没有实现设备设置功能。

默认使用用户提供的 27 英寸、2560×1440 显示器参数（108.8 PPI）。
按硬件契约的 4.26 英寸、800×480 计算 X4 约 219 PPI，显示区估算为
92.8×55.7 毫米。217 PPI 是契约中的近似值。实物模式把像素比除以浏览器
devicePixelRatio，考虑操作系统和浏览器缩放。仍需用尺量 50 毫米横线校准；
更换显示器后重新校准。像素一一对应和实物尺寸是两种不同模式。预览无法证明
墨水屏对比度、灰度波形、残影或真机可读性。

## 格式检查结果（2026-10-13）

历史验证的原文件只读来源：`backups/tf-card-2026-10-12_212440/fonts/`。
使用者可自行提供含三种字号的目录，默认读取 `backups/fonts/`。
完整源文件 SHA-256、覆盖范围及实际尺寸见生成目录中的 `preview_epdfont_report.json`。

纠正此前未验证的推断：`EPDF` 后的 `6D 00 00 00` 是 109 个区间的计数，
不是名为 EPDFm 的标识。三份文件均为：

- 48 字节文件头，109 个 Unicode 区间，21410 个字形；
- 12 字节区间记录，13 字节字形记录，连续 MSB 优先的 2 bit 位图；
- 位图包含四级灰度；当前单色预览将等级 2、3 画黑；
- 全部区间、21410 个字形的长度／偏移和文件末尾边界逐项检查通过；
- 字形偏移中出现 FF 00、FE 00 等，按这批文件的有符号 8 位位置还原为 -1、-2。
  该兼容处理仅用于已检查的 Zheng 文件，不宣称支持任意 EPDF 格式。

GB2312 范围由 Python 内置 `gb2312` 编码表逐项解码。三个字库均覆盖全部
6763 个汉字；总覆盖为 7063/7445，缺少 382 个非汉字符号。预览会对缺字显示
方框并提示，不用系统字体静默替代。ASCII 字库另有少量缺字。

| 字库 | “中”字形宽×高 | 汉字步进 | 原行距 |
| --- | --- | --- | --- |
| Zheng17 | 24×35 像素 | 35 像素 | 35 像素 |
| Zheng20 | 28×41 像素 | 42 像素 | 42 像素 |
| Zheng25 | 35×51 像素 | 52 像素 | 52 像素 |

项目固定的 OpenX4 SDK 没有字库解码器；公开社区 EPDF 转换器所述的
32 字节头／16 字节记录与这批文件不一致。本工具依据原文件结构进行离线检查，
没有引入社区固件、驱动或在线服务。现已选择原始 20 号字库按需读取方案，
固件实现和验证见 [firmware/FONT20.md](../../firmware/FONT20.md)。

## 再生成与验证

```powershell
.\.venv\Scripts\python.exe tools/font_preview/preview_epdfont.py --font-dir '本地字库目录'
```

脚本只依赖 Python 标准库，只读指定目录中的 `Zheng17号.epdfont`、
`Zheng20号.epdfont`、`Zheng25号.epdfont`，从工具目录的模板生成 HTML 和检查报告。
输出默认位于 `artifacts/font-preview/`，也可用 `--output PATH` 指定 HTML 路径，
报告随 HTML 放在同一目录。字体和生成产物不纳入 Git，仓库只保留工具与模板。
HTML 嵌入 GB2312 范围及可用 ASCII 字形，不嵌入整套源字体，文件约 12 MB。

已用本机 Edge 的无头浏览器检查：自动显示三块画布、DPR=1/1.5 时尺寸、
尺量校准／重置、黑白／灰度切换、自定义中文和缺字提示。无远程请求或
JavaScript 运行错误；历史截图 `preview_epdfont_qa.png` 和
`preview_epdfont_20_qa.png` 已人工查看，现保留在本机 `artifacts/font-preview/`。
这些验证不包含固件或 TF 硬件。
